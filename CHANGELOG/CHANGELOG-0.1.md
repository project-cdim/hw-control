# Changelog 0.1

## [0.1.1](https://github.com/project-cdim/hw-control/compare/v0.1.0...v0.1.1) - 2025-09-18

The changes from v0.1.0 are as follows:

### Features

- Added the Device Aggregation Control endpoint to the Device Control API to control the aggregation state between devices.

### Deprecations

- The legacy Aggregation Control endpoint, which controls the aggregation state between the Host-CPU and a device, is now deprecated and will be removed in a future release. As a result, the following exception classes have also been deprecated:
  - `HostCPUNotFoundHWControlError`
  - `HostCPUAndDeviceNotFoundHWControlError`

### Bug Fixes

- Fixed a bug where the Request ID was not correctly output in logs generated by Error Handlers.

### Documentation

- Changed the API documentation from Swagger UI to ReDoc.

- Added an introduction to the hw-control API specifications to the API documentation, including explanations of common concepts such as Device IDs and Error Codes as used in the hw-control API.

- Added descriptions of error response cases to the API documentation.

### Breaking Changes

- Migrated class names to follow PEP8 CapitalizedWords (CamelCase) convention (e.g., `CpuResetFailureHwControlError` to `CPUResetFailureHWControlError`).

- Replaced the [`cdim-python-logger`](https://github.com/project-cdim/cdim-python-logger) library with Python's built-in logger.

- Changed the HTTP status code returned for request parameter validation errors from `400` to `422`.

- Changed the HTTP status code returned for requests using undefined HTTP methods on existing paths from `400` to `405`.

### Other Changes

- Made the trailing `/` at the end of the following environment variable paths optional:
  - `HW_CONTROL_CONFIG_FILE_DIR`
  - `HW_CONTROL_DATA_FILE_DIR`

- Refactored the response generation logic in the Device Control API.

- Migrated deprecated code of Python 3.12 using pyupgrade.

- Improved the Device ID Manager API to consider for devices connecting to multiple ports.
